# 技术文章转载

将技术文章原文完整转载为可直接发布的 Markdown，保存到 `./posts/{year}/`。**正文保持原文一字不改**，只做必要的结构还原与广告清理。

转载稿与译文共用「译文集」（`/tech`）页面：该页按 `isOriginal: false` 筛选，不区分文件名前缀，靠标题前缀 `[译]` / `[转]` 区分类型。因此 `isOriginal` 必须为 `false`，否则不会出现在 `/tech`。

**何时使用**：用户要的是「原文留存」。常见的说法是「转一下这篇」「搬运到博客」「存个档」「把这篇原文放上去」。产物是原语言原文。

**何时不用**：用户要的是中文版，或说「翻译」「译成中文」。那时用 `translation-tech-article`。拿不准就看用户是否提到「保留原文」「不要翻译」。

如果用户给了外文链接但没说清楚，先确认是要中文版还是原样转载，别自己默认。

## 流程

### 0. 确认输入

- **无输入**：提示用户提供 URL、粘贴原文或文件路径，不猜测、不搜索、不编造。
- **只给了 URL**：抓取前先问一句「有已解析好的 Markdown 吗？有就贴过来或给路径」。有则等用户提供，无则直接抓取。
- 用户提供的文本残缺时，说明残缺范围再问是否照此转载。

### 1. 提取原文信息

从 URL / 粘贴内容 / 文件中获取：标题、作者、发表时间、原文链接。

- 优先用用户提供的解析文本；无时才抓取网页
- 抓取时先读 JSON-LD、`og:*` 拿元信息；抓不到正文（SPA、反爬、登录墙）就要求用户粘贴原文
- 无法确认的字段标 `未注明`，链接无法确认时标 `未提供`，**不得猜测**
- 原文不完整时明确说明转载范围，**不得谎称全文转载**
- 无网络访问时要求用户粘贴原文

### 2. 生成文件名与路径

- 目录：`./posts/{year}/`，`{year}` 取本次转载的 `date` 年份（不是原文发表年份）
- 文件名：`repost-<3–6 个由连字符分隔的小写英文/数字单词>.md`
- 写入前检查冲突；已存在则换一个合规 slug，**不得静默覆盖**

### 3. 原文还原与清理

**不改写、不删节、不润色、不重排论证、不替换术语**，保留原文结构、语气、代码、命令、示例、表格、引用、图片及必要链接与披露。

- 只做两件事：清理广告（无关推广、课程推销、站点导航、Cookie 提示、订阅表单），把原文结构还原为等价 Markdown
- 代码块需补语言标识（如 `js`、`html`），代码内容与注释**原样保留**
- 命令、标识符、URL、图片源原样保留
- 原文标点、大小写、空格、引号风格、中英混排方式**一律不动**（不套用盘古之白、不改 `「」`、不改斜体为加粗）
- 原文为英文或其他语言时，**不翻译**，正文保持原语言，仅在完成报告中说明原文语言
- 图片 alt 文本保持原文（即使为空也保持为空），不翻译
- 原文有脚注时保留脚注定义与引用

### 4. 排版并保存

按下方规范排版后写入文件，最后校验 YAML、链接、图片、代码围栏、slug、路径。

## 格式规范

- **忠实性**：原文即成品。除广告与结构外零改动，不确定的技术细节不修正、不补充
- **结构**：标题层级、列表、加粗、引用、代码围栏、表格、分隔线按原意还原
- **图片**：保留语法、来源、顺序
- **脚注**：仅需保留脚注引用，无需添加脚注标题（`## 脚注`），该标题会由解析器添加
- **其他**：其他非常规 Markdown 内容（如在线编辑器）降级为单段落链接文本

## Frontmatter 规范

| 字段 | 规则 |
|---|---|
| `title` | 以 `[转] ` 开头，后接原文标题（不翻译） |
| `date` | 本次转载生成日期 `YYYY-MM-DD`，须与目录年份一致 |
| `excerpt` | ≤40 字，概括核心内容，不写成宣传语。可中文概括 |
| `topic` | 仅 `技术` 或 `前端`；核心主题属前端时选 `前端` |
| `isOriginal` | 不加引号的布尔值 `false`（决定是否进 `/tech` 译文集，必填） |
| `author` | 原作者全名，未知填 `未注明`；最多列两人，第三位起用 `等`，如 `A、B 等` |
| `tags` | 3–6 个，必须含 `转载` |

## 输出模板

```markdown
---
title: '[转] 原文标题（不翻译）'
date: YYYY-MM-DD
topic: '技术'
excerpt: '一句话概括文章核心内容。'
isOriginal: false
author: '原作者完整姓名'
tags:
  - '相关主题'
  - '转载'
  - '其他相关标签'
---

> 原文：原文标题
>
> 时间：原文发表时间或「未注明」
>
> 作者：原作者姓名或「未注明」
>
> 链接：原文 URL 或「未提供」

---

（原文正文，保持原语言、原措辞。文末不加任何按语或说明。）
```

## 错误处理

| 场景 | 处理 |
|---|---|
| 未提供输入 | 提示提供 URL、原文或文件路径 |
| 给了 URL | 先问是否有已解析的 Markdown |
| URL 无法访问 | 重试；仍失败则要求粘贴原文 |
| 抓取只得空壳 HTML | 要求粘贴原文，不编造正文 |
| 目标文件已存在 | 换一个合规 slug，不覆盖 |
| 元信息无法确认 | 标 `未注明` / `未提供`，不猜测 |
| 原文非中文 | 不翻译，原样照登 |
| 原文有明显的拼写/代码错误 | 不擅自修正；可保留原文并在完成报告中提示 |
| 无网络 | 要求用户粘贴原文 |

## 完成检查

- [ ] 输入已确认（URL 场景问过是否有解析文本）
- [ ] 路径、slug（`repost-` 前缀）、目录年份合规，未覆盖已有文件
- [ ] Frontmatter 字段完整合法，`title` 以 `[转] ` 开头，`tags` 含 `转载`，`isOriginal: false`，`date` 与目录年份一致
- [ ] 正文与原文逐段一致，无改写、无删节、无翻译、无术语替换
- [ ] 广告清理干净，相关论据/资源/披露保留，代码块语言标识正确
- [ ] 图片/alt、链接、脚注完好且未改动
- [ ] 文末无「译者注」或任何附加按语
- [ ] 仅在写入成功后报告保存路径，说明未核实或未完整转载的内容
