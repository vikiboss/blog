# 技术文章翻译

将用户提供的技术文章翻译为符合中文技术社区习惯、可直接发布的 Markdown 文件，并保存到 `./posts/{year}/`。优先保证准确、完整、专业，兼顾原文风格与中文可读性；不得擅自摘要、删减论点或改写观点。

## 工作流程

1. **获取原文**：从 URL、正文或文件中提取原文标题、作者、发表时间和链接。提供 URL 时，尽可能核实原文信息；无法确认的元信息标为 `未注明`，链接无法确认时标为 `未提供`，不得猜测。原文无法完整获取时，明确说明翻译范围，不得将部分内容标为全文翻译。

2. **确定文件路径**：结合原文 slug（若有）和文章主题生成文件名，格式为 `translation-xxx-xxx.md`。slug 必须以 `translation-` 开头，由 3–7 个连字符分隔的单词组成（包含 `translation`），仅使用小写英文字母、数字和连字符。目录为 `./posts/{year}/`，其中年份与本次译文的 `date` 一致，而非原文发表年份。写入前检查文件是否存在；如发生冲突，选择符合规则的其他 slug，不得静默覆盖。

3. **翻译与清理**：完整翻译正文，忠实保留原文的语气、结构、论证和信息。统一技术术语，保留必要的图片、代码、命令、示例、表格、引用及资源链接。删除广告、无关推广、课程推销、网站导航和 Cookie 提示；保留与文章论点相关的产品、工具、项目、资源及必要披露。不得将正常的技术讨论误判为推广。

4. **排版与保存**：保留 Markdown 结构与内容顺序，遵循下方元信息、格式规范和输出模板。完成后检查 YAML、链接、图片、代码围栏、slug 和文件路径，确认写入成功。

## 翻译与排版规范

- **忠实性**：不擅自摘要、增补事实、删减论据或改变作者立场；不确定的技术细节不得自行编造。
- **代码与链接**：代码块原则上原样保留；不修改代码标识符、命令、URL 或图片源地址。翻译正文中的说明文字及适合翻译的图片 alt 文本。
- **图片**：保留相关图片的 Markdown 语法、来源、位置和顺序；翻译有意义的 alt 文本，不得编造图片内容或无故删除图片。
- **中文表达**：采用自然、准确、专业的中文，遵循中文技术社区惯例；专有名词和术语前后一致，必要时保留英文原词。
- **排版**：按盘古之白规则处理中英文及数字间的空格；中文 Markdown 链接整体与相邻中文之间留空格；中文引号使用「」。
- **内容清理**：仅清理与文章无关的页面杂项，不改变原文必要的披露、论据、引用与上下文。

## 元信息规范

- `title`：以 `[译] ` 开头，简洁准确。
- `date`：本次译文的生成日期，格式为 `YYYY-MM-DD`，使用当前日期；必须与目录年份一致。
- `excerpt`：一句话概括文章核心内容，不超过 40 字，不写成宣传语。
- `topic`：只能是 `技术` 或 `前端`；文章核心主题属于前端开发时选 `前端`，否则选 `技术`。
- `isOriginal`：固定为 YAML 布尔值 `false`，不得加引号。
- `author`：原作者全名；无法确认时写 `未注明`。
- `tags`：共 3–6 个贴合文章主题的标签，必须包含 `翻译`。

## 输出模板

```markdown
---
title: '[译] 简洁准确的中文标题'
date: YYYY-MM-DD
topic: '技术'
excerpt: '一句话概括文章核心内容。'
isOriginal: false
author: '原作者完整姓名'
tags:
  - '相关主题'
  - '翻译'
  - '其他相关标签'
---

> 原文：原文标题
>
> 时间：原文发表时间或「未注明」
>
> 作者：原作者姓名或「未注明」
>
> 链接：原文 URL 或「未提供」

---

（完整的中文翻译正文。）

---

## 译者注

本文由 AI 辅助翻译，译者进行了后期润色和校对。

```

## 完成检查

- [ ] 文件路径、slug 和目录年份符合规则；未覆盖已有文件。
- [ ] Frontmatter 字段完整、合法，`date` 与目录年份一致。
- [ ] 正文完整准确，术语一致，图片及 alt 文本处理正确，代码与链接未损坏。
- [ ] 无关广告已清理，相关论据、资源和必要披露均已保留。
- [ ] Markdown、盘古之白、中文链接空格及中文引号符合规范。
- [ ] 文章以译者注结尾；仅在确认文件写入成功后报告保存路径，并说明尚未核实的信息或未能完整翻译的内容。
